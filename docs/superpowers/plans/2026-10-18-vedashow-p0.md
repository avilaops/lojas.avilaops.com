# VedaShow P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Canonicalize verified VedaShow category aliases and legacy URLs without mutating production data.

**Architecture:** Pure libraries define category equivalence and host-scoped legacy redirects. The category page, admin consolidation route and proxy consume those rules while preserving existing multi-tenant boundaries.

**Tech Stack:** Next.js 16, React 19, TypeScript, Node test runner, Prisma 6.

**Spec:** `docs/superpowers/specs/2026-10-18-vedashow-p0-design.md`

## Global Constraints

- Do not mutate production data.
- Do not deploy or publish automatically.
- Redirect only verified legacy paths and preserve query parameters.
- Keep VedaShow-specific paths scoped to `vedashow.com.br`.

## Review Focus

- Another tenant requests a VedaShow legacy path and must not redirect.
- `www.vedashow.com.br` must canonicalize host without forming a redirect chain.
- A duplicate category that still owns products must remain directly accessible.
- Singular/plural and O-ring aliases must resolve to one equivalence key.
- Query parameters must survive legacy and category redirects.
